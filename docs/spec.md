# 输入框文字三档优化（Prompt Polish）— 设计规格

> 目标：在 DSH Web GUI 的 composer 上加一个「优化」入口（按钮 + 快捷键），把用户当前草稿文字做二次优化，**先预览、确认后回填**，全程保留用户原意。

> **v0.2.0 更新（照 TRAE「优化输入内容」的手感重做）**：入口从带文字的按钮改成**一个星星图标**；默认档位改为 `auto`（本地按长度/行数自选三档之一，不多发一次请求）；默认落地方式改为 `instant`（**直接回填** + 12 秒「已优化 · 档位 · 耗时｜撤销｜详情」提示条），`preview` 模式保留在长按/右键菜单里。下面第 1 节描述的是 v0.1 的纯预览流程，作为 `preview` 模式规格继续有效。

## 1. 交互流程

```
用户写草稿 → 点工具栏「优化」按钮 或 按快捷键
        ↓（取草稿全文；若存在选区则只优化选区）
  [面板展开] 档位：轻度 / 中度 / 重度（默认记住上次选择，初始「中度」）
        ↓ 自动用当前档位发起一次请求，面板内显示 loading
  [预览] 优化后文本 + 「改动要点」+「待确认项」
        ↓ 切档位 → 就地重跑（旧请求取消）
  [确认插入] → 写回草稿（无选区：整体替换；有选区：替换选区）→ 面板关闭，焦点回输入框
  [取消] / Esc → 丢弃结果，草稿一字不动
  [重试] → 请求失败时可用
```

关键约束：
- **草稿不被提前修改**：任何时刻点取消/关面板，草稿必须与触发前完全一致。
- **请求期间草稿被用户改动**：确认插入前比对快照。若原文已变化 → 不静默覆盖，改为「在你的改动之后插入结果」或提示重新优化（默认提示 + 提供「仍然替换」）。
- **空草稿**：按钮禁用（tooltip 说明）；只有附件时同样禁用。
- **超长草稿**：> 8000 字符时面板提示「建议先选中要优化的段落」，仍允许用户强制继续（截断到 8000 并标注）。

## 2. 三档定义（提示词层）

| 档位 | id | 允许改什么 | 禁止改什么 | 长度 | 验收 |
| --- | --- | --- | --- | --- | --- |
| 轻度 | `smooth` | 语法、错别字、标点、口语赘词、指代与衔接、术语统一 | 句序与段落结构、信息点、语气强度 | ±15% | 逐句读通，信息点一一对应 |
| 中度 | `structure` | 上述 + 分点/编号/顺序词、显式化隐含约束（对象、范围、格式、禁止项）、合并拆句、调整段落顺序 | 新增事实、参数、需求；删掉任何信息点 | 可 +60% | 每条信息都能在原句找到出处 |
| 重度 | `instruction` | 重组成明确指令：目标 / 输入 / 约束 / 输出格式 / 验收标准；模糊词收敛为可执行描述 | 臆造事实与参数；改变意图或优先级 | 可 +120%，但保持可读 | 任何人都能照着执行，且不引入原文没有的要求 |

## 3. 必须原样保留的 token（硬约束）

保留清单（提示词 + 后置校验双保险）：
- `@` 文件/会话引用 token（如 `@src/app.ts`）
- `/` 斜杠命令（如 `/compact`、`/goal`）
- Markdown 代码块与行内代码（``` / `` ` ``）
- URL、绝对/相对路径、环境变量名、函数名、标识符、flag（如 `--risk 2`）
- 数字、单位、版本号、端口、IP、域名
- 用户显式写的引用片段（引号内的原文）

后置校验（客户端做）：
1. 从原文提取上述 token 集合；
2. 若结果缺失任一项 → 判为「可能丢失关键内容」，在预览里显著标红缺失项，并默认降一档重跑一次（`instruction → structure → smooth`）；
3. 仍缺失则只提示、不阻拦（用户可自行确认）。

## 4. 输出协议

模型返回 JSON（解析容错：先剥 ```json 围栏，再尝试首个 `{...}` 块）：

```json
{
  "text": "优化后的完整文本",
  "notes": ["改动要点，3 条以内，每条 ≤ 20 字"],
  "assumptions": ["为保持可执行而补的假设；没有则空数组"]
}
```

面板渲染：`text` 预览区（可滚动、可编辑——允许用户在预览里微调后再插入）；`notes` 小字列表；`assumptions` 单独一行提示「以下为补全的假设，请确认」。

## 5. 系统提示词（原文，直接注入）

```
你是 DSH 输入框的「指令润色器」。用户会给你一段他准备发给 AI Agent 的原文，以及要求的优化档位。你的任务是让这段话更好用，但绝不能改变他的本意。

绝对规则（任何档位都适用）：
1. 不新增事实、参数、需求、要求；不删掉任何信息点；不改变意图、优先级、语气强度。
2. 原文中出现的这些必须逐字保留：@引用、/命令、代码块与行内代码、URL、路径、环境变量、标识符、命令与参数、数字与单位、版本号、IP/端口/域名、引号内原文。
3. 保持原文语言（中文写中文，英文写英文，中英混排照旧），不要翻译，不要加解释性前言或总结。
4. 只输出 JSON：{"text": "...", "notes": ["..."], "assumptions": ["..."]}。text 必须是可直接替换原文的成品；notes ≤3 条，每条 ≤20 字；没有假设就给空数组。
5. 如果原文已经足够好，就在 text 里原样返回，notes 写「原文已清晰」。

档位（按用户给的 level 执行，只做该档允许的事）：
- smooth：只做语法、错别字、标点、赘词、指代与衔接的顺滑处理；句子顺序和段落结构不动；长度变化不超过 ±15%。
- structure：在 smooth 的基础上，把隐含的结构显式化——该分点的分点、该编号的编号、该补的约束（对象/范围/输出格式/禁止项）用原意补明确；可以合并拆句、调整段落顺序；长度可以增加，但每一句都要能在原文找到出处。
- instruction：重组成一条明确、可直接执行的指令，通常包含：目标、输入/上下文、约束（含禁止项）、输出格式、验收标准；把模糊表述收敛成可执行描述；原文没给的参数要么不写，要么放进 assumptions 并明确标注「待确认」。
```

## 6. 用户消息模板

```
level: {{smooth|structure|instruction}}
locale: {{zh|en|...}}
原文：
<<<
{{draft}}
>>>
```

## 7. UI 规格

- 入口：composer 工具栏行加一个图标按钮（`优化`，图标用文字 `Aa` 或 sparkle），悬停 tooltip：`优化输入（Ctrl+Alt+P）`。
- 快捷键：`Ctrl+Alt+P`（macOS `Cmd+Alt+P`），可在设置里改（若宿主快捷键系统支持）。
- 面板：贴在 composer 上方，卡片式，宽与 composer 一致；顶部一行：`优化输入` + 三档分段控件（轻/中/重）+ 关闭 ×；中部：预览文本（等宽/正文字体，最大高 40vh 滚动）；底部：`补全的假设`（若有）+ `改动要点` + 右侧按钮 `取消` `确认插入`。
- 视觉沿用 DSH 现有 token（背景/描边/圆角/字号/间距），不引入新色板；loading 用骨架闪烁而非 spinner 旋转（与 DSH 现有骨架一致更好）。
- 键盘：面板内 `Esc` 关闭；`Ctrl/Cmd+Enter` = 确认插入；Tab 在档位间切换。

## 8. 失败与降级

| 情况 | 行为 |
| --- | --- |
| 未配置可用模型 / 401 | 面板内错误行 + `重试`；草稿不动 |
| 超时（默认 45s） | 取消请求，提示可重试；可切轻档重试 |
| 返回非 JSON | 兜底：把整段返回当 `text`，notes 空 |
| 结果与原文完全相同 | 提示「原文已足够清晰」，提供返回草稿按钮 |
| 关键 token 缺失 | 标红缺失项 + 自动降档重跑一次 |

## 9. 不做的事（YAGNI）

- 不做多轮对话式追问；
- 不做历史版本管理（宿主草稿本身可撤销）；
- 不做流式渲染（一次返回，预览即可）；
- 不写入 Session 记录（不产生对话轮次）。
